# Кодекс взаимодействия команд Ticketland и KION по платформе UMC

**Версия 0.3 от 05.10.2026** · проект к согласованию 06.10.2026
**Стороны:** команда Ticketland — А. Ишманов · команда KION, владелец платформы UMC — *владелец на подтверждение*

## 1. Проблема

- **Витрина Ticketland зависит от платформы UMC.** Через UMC идут каталог кино, мероприятия TicketsCloud и доступность билетов. По плану Q4 через неё пойдут и заказы TicketsCloud в личном кабинете.
- **Ticketland и KION могут стать разными юрлицами.** Сейчас взаимодействие держится на рабочих чатах и личных договорённостях. Нет правил уведомления, владельцев, сохранения доступов и плана выхода.
- **Часть доработок UMC делает команда Ticketland** — те, что нужны в основном Ticketland. Если доступ к коду UMC пропадёт, эти доработки остановятся.

## 2. Решение

Команды принимают короткий свод правил, который действует независимо от оргструктуры:

1. Интеграция с UMC — продукт с контрактом, а не договорённость между людьми.
2. Никаких односторонних отключений: только уведомление заранее и план перехода.
3. У интеграции есть владелец в каждой команде.
4. Решения записываются в этот документ.

## 3. Договорённости

| # | Договорённость | Что предлагает Ticketland | Решение 06.10 |
|---|---|---|---|
| 1 | Отключение или разрыв потока | Уведомление не позднее чем за 90 дней, план миграции, параллельная работа старого и нового пути | |
| 2 | Владельцы интеграции | Ticketland — Ишманов; KION — назначить | |
| 3 | Изменения API, Kafka, форматов UMC | Анонс за 2 недели; изменения, ломающие совместимость, — только с планом миграции | |
| 4 | Задачи между командами | Каждая команда ведёт задачу в своей Jira со связью; Ticketland получает право создавать задачи в проекте UMC или отдельную очередь | |
| 5 | Доработки UMC силами Ticketland | Код и выкладка — за KION, ревью до 5 рабочих дней, ошибки своей функциональности исправляет Ticketland, доступ к репозиториям и стендам UMC сохраняется | |
| 6 | Инциденты | Задача + сообщение в чате техподдержки; целевая реакция: P1 — до 1 часа, P2 — до 1 рабочего дня (без обязательств) | |
| 7 | Доступы | Реестр доступов, сервисные учётки вместо личных, ротация ключей с уведомлением; при разделении доступы сохраняются | |
| 8 | Данные | Персональные данные через UMC не передаются; KION отвечает за каноникализацию в UMC, Ticketland — за данные витрины | |
| 9 | План выхода | KION даёт полный снимок данных UMC, нужных витрине; согласовываем резервный путь TicketsCloud → Ticketland | |
| 10 | Юридическое оформление | Выбрать форму (соглашение, приложение к договору или регламент), назначить владельцев и срок, решить, остаются ли потоки бесплатными при росте объёмов; до подписания команды работают по этому документу | |

**Минимум на 06.10:** пункты 1, 2 и 10. Остальное, если не успеем, — поручения с ответственным и сроком.

---

**Справочно — потоки через UMC**
- Ticketland → UMC: CDC-выгрузка каталога, BootStrap репертуара, Kafka `c-basis-to-live`.
- UMC → Ticketland: каталог кино (MRS → UMC → LoaderService → web_db), мероприятия TicketsCloud в обход БАЗИС, доступность через GraphQL и Kafka `umc-push-references` / `availability-push-references`.
