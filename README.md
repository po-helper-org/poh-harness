# poh-harness

Готовый к работе контур **DeepSeek Harness** с плагинами и настройками po-helper:
клонируете репозиторий, запускаете установщик, подключаете свою подписку — и
получаете рабочее место PO, а не голый харнесс, который ещё неделю настраивать.

## Что внутри

| Слой | Что даёт |
|---|---|
| **Раздел «Управление требованиями»** (`dsh-plugin-bft`) | Очередь БФТ из Backlog.md прямо в сайдбаре: поиск, превью требования, детальная страница с HTML-документом и мини-чатом, доска по стадиям проработки. Любое действие уводит в чат с готовым черновиком — отправляет всегда человек. |
| **Подписки как провайдеры** (`dsh-plugin-subscriptions`) | ChatGPT (Codex), Claude, Grok (X Premium), GitHub Copilot как LLM-провайдеры харнесса, вход по OAuth со страницы настроек. |
| **Backlog.md как нативные инструменты** | Задачи, доска и поиск по бэклогу доступны модели напрямую, без копипаста. |
| **Context7** | Актуальная документация библиотек в инструментах модели. |
| **Скиллы po-helper** | `poh-bft-writer`, `poh-okr-agent`, `poh-helper` подключены submodule'ами — семейство `/bft-*` и базовый набор PO доступны сразу, плюс скиллы вашего воркспейса. |
| **Демо-воркспейс** | Синтетические задачи БФТ на разных стадиях — раздел требований содержателен сразу после установки, без своего рабочего каталога. |
| **Эксплуатация** | Скрипт запуска, автозапуск при логине (macOS launchd / Linux systemd), разбор известных грабель. |

Сам харнесс сюда не скопирован: установщик ставит `@deepseek-ai/dsh` обычной
npm-зависимостью на закреплённую проверенную версию — как `npx @deepseek-ai/dsh
web` в апстриме, без клонирования исходников. Так контур обновляется отдельно
от апстрима, а не расходится с ним форком.

## Как развернуть

Нужны **Node.js 22.19+ (или 24+)**, **pnpm 11.7** и **git**.
Полезно, но не обязательно: [Backlog.md](https://github.com/MrLesk/Backlog.md)
(`npm i -g backlog.md`) — без него раздел требований будет пустым.

```sh
git clone --recurse-submodules https://github.com/po-helper-org/poh-harness.git
cd poh-harness
./install.sh                    # Enter — демо-воркспейс, или свой путь
./scripts/start-web.sh          # напечатает ссылку с токеном
```

Дальше — [docs/ONBOARDING.md](docs/ONBOARDING.md): подключение подписки и
настройка окружения под ваш воркспейс.

> **Рабочий каталог** — это репозиторий, требования которого вы ведёте (внутри
> `backlog/` и `bft/`), а не каталог харнесса. Установщик спросит путь; пустой
> ответ поднимает демо-воркспейс из этого репозитория.

## HowToDemo

1. Открываете репозиторий.
2. `git clone --recurse-submodules` + `./install.sh` (Enter на вопрос про
   воркспейс — демо-данные).
3. Получаете харнесс со всеми доработками и плагинами — раздел требований на
   демо-задачах, доска, Backlog.md и скиллы уже подключены.
4. Подключаете свою подписку на странице настроек ([шаг 4](docs/ONBOARDING.md#шаг-4--подключить-подписку)).
5. Проходите полный сценарий — [docs/HOWTODEMO.md](docs/HOWTODEMO.md).
